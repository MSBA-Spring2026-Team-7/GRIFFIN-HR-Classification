System Overview

GRIFFIN (Government Role Identification and Financial Framework Integration Network) is an AI-powered HR classification system built for William & Mary's Human Resources department. It combines web-scraped DHRM reference data, supervised machine learning, and LangChain multi-agent orchestration to classify position descriptions and recommend pay grades.

1

Data Pipeline Done

DHRM web scrape (56 career groups from Virginia HR) + Workday API scrape (150 W&M postings, 103 staff retained). Produces 7 reference Excel files and 4 training CSVs.

2

ML Pipeline Done

Regex-based feature engineering (15 features from censored PDs) fed into H2O AutoML. Trains multi-class classifier on 7 DHRM occupational families with 5-fold stratified CV, SHAP explanations, and PDP plots.

3

LangChain Agents Done

767-line multi-agent classification system using LangChain + Google Gemini. Loads all 7 reference Excel files as tool context. Implements 8 components: LLM init, agent creation, message handling, streaming, custom tools, external API tools, memory, and orchestration.

4

Streamlit App To Do

Frontend web application. HR user pastes a position description, the system classifies it and recommends a pay grade with full reasoning. Planned to integrate all three layers above.

How to Run Each Layer

Run notebooks 1 through 5 in order. Each builds on the outputs of the previous step. Activate the griffin conda environment before running any notebook.

What it does:

  • Installs all dependencies: requests, BeautifulSoup, pdfplumber, pandas, SQLAlchemy, Streamlit, SHAP, LangChain, LangGraph
  • Writes environment.yml for reproducibility
  • Registers the Jupyter kernel as "GRIFFIN (conda)"

Verify: Run conda activate griffin then python -c "import langchain; print(langchain.__version__)"

Notebook 2: DHRM Pipeline Done

File: notebooks/2_dhrm_pipeline.ipynb

Prerequisites: Environment set up (NB1). Internet access for DHRM website scraping.

What it does:

  • Scrapes all 56 DHRM career group pages (50 HTML + 6 PDF) using BeautifulSoup, requests, and pdfplumber
  • Parses career groups, roles, historical titles, and SOC codes into structured DataFrames
  • Loads data into SQLite/MySQL database via SQLAlchemy
  • Exports 7 reference Excel files to data/reference/

Run:

jupyter notebook notebooks/2_dhrm_pipeline.ipynb

Expected output: 7 Excel files in data/reference/: career_groups.xlsx, roles.xlsx, soc_codes.xlsx, historical_titles.xlsx, dhrm_pay_bands.xlsx, wm_pay_grades.xlsx, crosswalk.xlsx

Verify: Check data/reference/ contains all 7 files. Open career_groups.xlsx and confirm 56 rows.

Note: Raw HTML/PDF cache is stored in data/cache/raw_pages/ (gitignored). If you need to re-run, the cache prevents re-scraping the DHRM server.
Notebook 3: Workday Scrape Done

File: notebooks/3_workday_scrape.ipynb

Prerequisites: Environment set up (NB1). Internet access for W&M Workday API.

What it does:

  • Hits the W&M Workday REST API to pull 150 job postings (8 list pages + 150 detail pages)
  • Excludes 47 faculty postings (not classifiable under DHRM), retaining 103 staff positions
  • Strips classification labels from position description text to prevent label leakage during ML training
  • Exports training data to data/training/

Run:

jupyter notebook notebooks/3_workday_scrape.ipynb

Expected output:

  • data/training/workday_postings.csv -- full dataset (103 rows)
  • data/training/workday_training.csv -- censored PDs with labels (103 rows)
  • data/training/workday_exclusions.csv -- 47 excluded faculty postings

Verify: workday_training.csv should have 103 rows and 6 columns. Confirm no career group names or codes appear in the censored text.

Note: Raw JSON is cached in data/cache/raw_workday/ (gitignored). Never re-fetch from Workday if the cache exists.
Notebook 4: Feature Engineering Done

File: notebooks/4_feature_engineering.ipynb

Prerequisites: NB3 complete (workday_training.csv must exist).

What it does:

  • Extracts 15 structured features from 103 censored position descriptions using regex
  • Features include: budget mentions, supervision (gives/receives), education level (ordinal 0-5), years of experience, text length, 6 domain keyword counts (leadership, technical, research, healthcare, facilities, finance), exempt status, salaried flag
  • Maps 30 W&M job families to 7 DHRM occupational families
  • Produces feature correlation heatmap and distribution plots

Run:

jupyter notebook notebooks/4_feature_engineering.ipynb

Expected output: data/training/workday_features.csv (103 rows, 18 columns: 15 features + 3 label columns)

Verify: Open the CSV and confirm 15 numeric feature columns plus occ_family with 7 distinct values (plus "Unknown" for 3 NaN rows).

Notebook 5: H2O AutoML Done

File: notebooks/5_h2o_automl.ipynb

Prerequisites: NB4 complete (workday_features.csv must exist). Java JDK 11+ installed. H2O installed in the griffin environment.

What it does:

  • Loads the 103-row feature matrix and drops 3 "Unknown" rows (100 usable observations)
  • Trains H2O AutoML with 5-fold stratified cross-validation (5 minutes, logloss metric)
  • Generates leaderboard ranking GBM, XGBoost, GLM, DRF, Deep Learning, and stacked ensembles
  • Produces: confusion matrix, top-3 accuracy, variable importance, global SHAP, local SHAP, and partial dependence plots

Run:

jupyter notebook notebooks/5_h2o_automl.ipynb

Expected output: Trained model saved to models/ (gitignored). SHAP and PDP plots displayed inline.

Verify: Check the leaderboard output and confusion matrix. Top-3 accuracy should be reasonable given the small sample size (100 rows, 7 classes).

Java required: H2O is Java-based. The notebook sets JAVA_HOME automatically from the conda prefix, but JDK 11+ must be installed. See the Environment Setup section below.

Quick Start: Classify a Position Today

Fastest path to value. You do not need to run any code, install any packages, or set up any environment. This workflow uses your existing LLM tool (Microsoft Copilot, Google Gemini, Claude, or similar) with GRIFFIN's reference data and a pre-built prompt template.

Step 1: Get the prompt template

Open app/prompts/classification_prompt_v1.md and copy the entire PROMPT section (everything inside the code fence). This prompt instructs the LLM to act as a DHRM classification and compensation analyst.

Step 2: Attach reference data

Upload or paste these two Excel files from data/reference/:

  • career_groups.xlsx -- 56 DHRM career groups with codes, occupational families, and concepts of work
  • roles.xlsx -- all roles within each career group, with pay bands and compensable factors

Optionally also attach crosswalk.xlsx and dhrm_pay_bands.xlsx for pay matching.

Step 3: Paste a position description

Replace the [POSITION DESCRIPTION] placeholder in the prompt with the actual PD text. The LLM will analyze it against the reference data and produce:

  • Primary career group classification with confidence percentage
  • Matched role within the career group
  • Pay band recommendation
  • Full reasoning chain explaining the classification
  • Blended classification if duties span multiple career groups (configurable threshold)

Step 4: Review and iterate

The output includes a reasoning chain you can audit. If the classification seems off, check whether the PD was too vague or if a blended classification (multiple career groups) is more appropriate. Adjust the BLEND_THRESHOLD in the prompt configuration section (default: 30%).

Architecture Decisions

Why hybrid ML + LLM?

The ML model (H2O AutoML) provides fast, consistent shortlisting of candidate career groups from structured features. The LLM (via LangChain agents) adds explainability by reading the full position description text and referencing the DHRM career group narratives. ML handles the quantitative signal; the LLM handles the qualitative reasoning. This satisfies both the Big Data rubric (ML with SHAP) and the AI rubric (multi-agent orchestration).

Why 7 occupational families, not 56 career groups?

With only 103 training observations, classifying into 56 career groups would give fewer than 2 examples per class on average. The 7 DHRM occupational families (Administrative Services, Engineering and Technology, etc.) provide a meaningful and trainable target. The LLM agent then drills down from the ML's top family prediction into the specific career group and role using the reference data narratives.

Why censored position descriptions?

The raw Workday PDs contain job family names, career group references, and classification codes in their text. If the ML model trained on uncensored text, it would simply memorize the labels embedded in the descriptions rather than learning the actual job content signals. Notebook 3 strips these labels to prevent leakage, forcing the model to learn from genuine content features like supervision level, education requirements, and domain keywords.

Why H2O, not scikit-learn?

H2O AutoML trains and tunes multiple model families (GBM, XGBoost, GLM, DRF, Deep Learning, stacked ensembles) in a single call, producing a ranked leaderboard. With only 100 observations and 7 classes, manual hyperparameter tuning would be unreliable. AutoML explores the model space systematically. H2O is also Java-based, making it suitable for production deployment. The Big Data course covers H2O as part of the toolkit.

Why LangChain + Google Gemini?

LangChain's init_chat_model() provides LLM-agnostic design: W&M HR can swap between Gemini, Copilot, or Claude by changing a single config string, with no code changes. This is a client requirement since W&M uses both Microsoft Copilot and Google Gemini. LangGraph adds state-machine orchestration for the multi-agent workflow, satisfying Assignment 5's orchestration component.

Environment Setup

Conda Environment

The project uses a conda environment named griffin with Python 3.11. Recreate it from the spec file:

conda env create -f environment.yml
conda activate griffin

Or create manually and install packages:

conda create -n griffin python=3.11 -y
conda activate griffin

# Conda packages (binary-compatible)
conda install -c conda-forge requests beautifulsoup4 lxml pandas \
  sqlalchemy pymysql openpyxl streamlit plotly seaborn matplotlib \
  shap ipykernel -y

# Pip-only packages
pip install pdfplumber langchain langchain-core langgraph

Packages installed (16 total): requests, beautifulsoup4, pdfplumber, lxml, pandas, sqlalchemy, pymysql, openpyxl, streamlit, plotly, seaborn, matplotlib, shap, langchain, langchain-core, langgraph

Java for H2O

H2O AutoML is Java-based and requires JDK 11 or later. Notebook 5 sets JAVA_HOME automatically from the conda prefix, but the JDK must be installed.

Option A (recommended): Follow the Big Data course lab setup process for H2O installation. The lab walkthrough covers Java dependencies and troubleshooting.

Option B (manual):

# Install Java into the conda environment
conda install -n griffin -c conda-forge openjdk=11 -y

# Install H2O (pip)
conda run -n griffin pip install h2o

Verify:

conda activate griffin
python -c "import h2o; h2o.init(); print(h2o.cluster().status)"

API Keys

Copy the template and fill in your keys:

cp .env.example .env
# Edit .env with your actual API keys

Required keys:

  • GOOGLE_API_KEY -- Google Gemini API key (required for LangChain agents)

Optional keys:

  • TAVILY_API_KEY -- Tavily search API (for web search tool in Component 6)
  • CAREERONESTOP_TOKEN -- CareerOneStop API token (for external salary data)
  • CAREERONESTOP_USER_ID -- CareerOneStop user ID
Never commit .env files. The .gitignore excludes .env at all directory levels. The .env.example template contains placeholder values only.
